## 1. プロジェクト概要

- **アプリ名（仮）**: カラオケ選曲メモ
- **一言で言うと**: カラオケで「あの曲のキー、何度だったっけ」を解消し、音域に合ったキー・気分やシチュエーションに合った曲を記録・検索できるアプリ
- **現在のフェーズ**: MVP（最小限の機能で動くバージョン）の開発
- **ベーステンプレート**: Next.js and Supabase Starter Kit（認証まわりの土台が導入済み）

## 2. アプリのゴール（WHO / WHAT / HOW）

- **WHO（誰のための）**: カラオケで「歌いたい曲はあるのに、キーや感想を忘れてしまう」人。まずは開発者本人、将来的には友人。
- **WHAT（何を解決するか）**: 歌った曲のキー調整・感想・シチュエーションに合う曲を、カラオケのその場で記録・検索できるようにし、選曲の迷いや時間のロスをなくす。
- **HOW（どう解決するか）**: 「シチュエーション（大項目）→ 曲 → キー等の詳細」という段階的な絞り込みと、曲名・歌手名でのダイレクト検索の両方を、カラオケ中にスマホから片手でサッと使えるUIで提供する。

## 3. ターゲットユーザー詳細

### フェーズ1（MVP）: 開発者本人のみ
カラオケボックスの中で、スマートフォンからその場で使うことを前提とする。

| 利用シーン | 内容 |
|---|---|
| 登録 | 歌った直後、その場で「このキーで良かった」とキーや感想を記録する |
| 検索（シチュエーション） | 友人とカラオケに行った際、自分の得意な曲や今の気分に合う曲を瞬時に探す |
| 検索（キーワード） | 曲名・アーティスト名を覚えている場合、直接検索する |

### フェーズ2（MVP後）: 友人にも展開
- ユーザーごとに独立した曲リストを持つ（他人のリストは基本見えない）
- 曲リストは基本非公開。別途「公開用リスト」を作成し、公開したい曲だけを友人に見せられるようにする

## 4. 主要機能（MVP / 将来機能の分類）

### MVP（最初のリリースで必須）

| 機能 | 内容 |
|---|---|
| かんたんログイン | 個人ごとにデータを分けて保存できる、シンプルなユーザー識別 |
| 曲の登録 | 曲名・歌手名・キー・要確認フラグ・満足度・シチュエーションを記録 |
| シチュエーション管理 | 初期項目の用意＋自分での追加・編集・削除 |
| シチュエーションで探す | 大項目 → 曲一覧 → キー等の詳細、の順で絞り込み |
| 曲名・歌手名で検索 | 自分の登録済みの曲からサジェスト付きで検索 |
| 曲の編集・削除 | 登録内容の修正・削除 |

### MVP後に追加したい機能

| 機能 | 内容 |
|---|---|
| 友人との共有 | 曲リストは基本非公開。別途「公開用リスト」を作成し、公開したい曲だけを友人に見せられるようにする |
| フレンド共有（共通曲表示） | 友だちとリストを共有した際に、「いいね」のように、お互いの共通曲がひと目でわかる仕組みを作る（優先度: かなり低） |

## 5. UI/UX方針

- **モバイルファースト**: カラオケボックス内でスマホから片手操作できることを最優先にする
- **曲一覧は1行に簡潔にまとめる**: 曲名・キー・要確認マーク（1文字程度）・満足度を1行に収め、多くの曲を一目で見渡せるようにする（詳細情報はタップ後の詳細画面で見せる）
- **入力の手間を最小化する**:
  - 曲名・アーティスト名は「自分が過去に登録した曲」からのサジェスト入力のみ（外部の曲データベース連携はしない）
  - キーの入力は＋／－ボタンのみのシンプルな操作
  - シチュエーションは複数選択可能
  - シチュエーションタグは登録画面からその場で新規作成できる（専用の管理画面に行かなくても良い。ボタンは控えめ・目立たない配置でよい）
- **ホーム画面構成**: 画面上部に「探す」「登録する」ボタン、その下にシチュエーション大項目の一覧を表示

### 画面一覧（MVP）

| 画面 | 内容 |
|---|---|
| ① ログイン | 簡易的なユーザー識別 |
| ② ホーム | 上部に「探す」「登録する」ボタン、下にシチュエーション大項目の一覧 |
| ③ 曲一覧 | シチュエーション選択後、または検索結果として表示。1行＝曲名・キー・要確認マーク・満足度 |
| ④ 曲詳細 | 一覧から曲をタップした後の詳細表示。編集・削除への入口 |
| ⑤ 曲登録・編集 | 曲名/アーティスト名（サジェスト入力）、キー（＋／－ボタン）、要確認、満足度、シチュエーション（複数選択・その場で新規タグ作成も可） |
| ⑥ 検索 | 曲名・アーティスト名を入力するとサジェスト付きで絞り込み検索 |
| ⑦ シチュエーション管理 | 大項目の追加・編集・削除 |

## 6. 技術仕様

- **フレームワーク**: Next.js（App Router）+ React 19 + TypeScript
- **スタイリング**: Tailwind CSS + shadcn/ui（Radix UIベース）
- **認証・データベース**: Supabase（`@supabase/supabase-js`, `@supabase/ssr`）
  - 認証: Supabaseの認証機能を使い、MVPの段階から簡易的なユーザー識別（ログイン）を実装する
  - データ保存: Supabaseのデータベース（Postgres）にテーブルを作成し、ユーザー・曲・シチュエーション・（将来）公開リストを管理する

### データ設計の方針

- 情報の種類ごとにテーブルを分ける想定: 曲（曲名・歌手名・キー・要確認・満足度）／シチュエーション（大項目名）／ユーザー／（MVP後）公開リスト
- 曲テーブルは「登録したユーザー」と紐付ける
- 曲とシチュエーションは多対多の関係のため、間に対応表（中間テーブル）を用意して紐付ける
- 削除時の方針（提案・要確認）:
  - ユーザーを削除した場合、そのユーザーの曲データも一緒に削除する（持ち主不明の曲を残さないため）
  - シチュエーション（大項目）を削除した場合、曲自体は消さず、そのタグが外れるだけにする（曲の記録は残すため）
- 曲名・歌手名・シチュエーションなど、よく検索に使う項目にはあらかじめ索引を用意し、曲数が増えても検索が遅くならないようにする。一覧表示も全件を一度に出さず、少しずつ表示する

## 7. 開発ロードマップ

1. 認証（ログイン）まわりの確認・調整
2. 曲の登録・一覧・検索・詳細・編集削除（MVPのコア機能）
3. シチュエーション管理（初期項目の用意、追加・編集・削除）
4. ホーム画面の統合（探す／登録するボタン＋シチュエーション一覧）
5. （MVP後）公開用リスト・友人との共有機能

## 8. 成功基準

- 実際のカラオケの場で、このアプリだけを頼りに、次に歌う曲をキー付きで選べること
- 曲の登録から検索までを、カラオケの短い待ち時間の中でストレスなく完了できること（操作のシンプルさ）
- 将来的に友人に勧めた際、抵抗なく使ってもらえる程度に使いやすいこと
